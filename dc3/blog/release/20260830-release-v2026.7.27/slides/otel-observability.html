IoT DC3 · Release R5 v2026.7.27 · 特性详解 3/3

配套底座：OpenTelemetry 全链路追踪、日志脱敏与供应链加固

缓冲解决"不丢数"，可观测解决"出了问题找得到"——两者是同一件事的两面
OpenTelemetry 怎么接入的
1
引入 OTel BOM 依赖治理
追踪相关依赖统一由 BOM 管版本，避免各模块自带版本漂移
2
融入 request-id 机制 关键设计
不是另起一套 trace 标识，而是把 span 上下文织入既有 request-id 传递链——日志里的 request-id 与 Jaeger 里的 trace 同源，两套系统互查无翻译成本
3
Jaeger 进可选栈 零成本试用
Jaeger 后端加入可选 docker-compose 栈：想要全链路追踪时一条命令拉起，不想要则零开销
同窗口的安全加固
日志脱敏：标识符与模型名（identifiers & model names）在日志输出前脱敏——排查问题与合规两不误
供应链：GitHub Actions 与 CodeQL 工作流固定到不可变 commit 哈希，杜绝 tag 被动后注入
健壮性：数字解析统一防御 NumberFormatException，脏数据进不来就不抛未捕获异常
为什么一起做：可观测与安全共用同一套"看得清"的基建——看得清才能守得住
文档工程同步升级
文档版本化系统：docs 站支持多版本文档并存，随发版节奏对齐
107 张 mermaid 图转自包含 SVG：渲染不再依赖运行时 JS，加载更快、离线可读
SEO 与统计：sitemap / robots.txt / llms.txt、GA4 与百度统计接入、图缩放增强
构建目标：Makefile 新增文档构建 targets 并固定 Node 版本，文档也能一键复现
本版本完整口径：不丢数（缓冲）+ 找得到（追踪）+ 看得清（脱敏与供应链）——可靠性是一组工程，不是一个开关
