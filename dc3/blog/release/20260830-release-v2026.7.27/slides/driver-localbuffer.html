为什么选 SQLite 而不是内存队列
重启不丢：驱动进程崩溃 / 升级重启，内存队列全灭；SQLite 落盘配合卷挂载，数据跨生命周期存活
驱动是边缘角色：跑在离设备最近的节点上，网络抖动是常态而非异常——暂存是常态能力，不是异常处理
依赖轻：sqlite-jdbc 单文件嵌入式，不引入额外存储服务——驱动的部署复杂度不变
缓冲容量与行为经 buffer config properties 配置化，随部署档位调整
与数据中心缓冲如何配合
两道防线各守一段：驱动侧守"发不出去"（本地落盘），数据中心守"写不进来"（有界背压）
重发数据进入正常消费链路，经数据中心缓冲统一批处理——补投不破坏下游节奏
全链路行为有缓冲单元测试覆盖（提交 18eac787），参数经 PointBatchProperties 配置化
设计取向：每一跳的失败都有去处——没有"尽力而为"，只有"明确暂存、明确重试"
一句话：网络恢复后的第一件事，是把断线期间攒下的数据一秒不差地补回去
