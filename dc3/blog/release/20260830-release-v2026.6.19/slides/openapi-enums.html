IoT DC3 · Release R2 v2026.6.19 · 特性详解 2/3

契约层升级：springdoc OpenAPI 全量文档化与枚举规范化

AI 的"表达层"升级之外，平台的"契约层"同步收敛——对接方从此照文档写代码
OpenAPI 文档化：做了什么
springdoc 接线：OpenAPI 文档端点上线，安全链加载同步修正
@Schema 全实体注解：dc3-common-dal 实体类全量标注——文档里的每个字段都有出处
文档化工具链：API 文档指南、导出工具与书写约定成文（提交 8a2a87f96）
为什么值得做
开源平台的集成方第一件事是读 API 文档——文档即门户，比任何推广语都有说服力
注解跟着实体走，代码与文档不会分叉——这是活文档，不是一次性截图
为 MCP 工具面的参数 Schema 打前站：同一套实体，两处消费
枚举规范化：怎么做的
领域枚举标准化（提交 72515d9f3）：command history 的 source / type / status 统一为 enum index 契约
命令历史来源字段类型化为枚举名，前后端类型对齐（提交 b61cc0f5a / 0d55b4d86）
对象边界（object boundaries）一并整理，测试随枚举重命名对齐
契约形态示例
"source": "manual..."（自由字符串）→"source": 2 (enum index，语义确定)
为什么现在做
枚举是最小单位的契约：自由字符串早晚长成脏数据
AI 工具面即将消费这些字段——模型需要确定的取值域，不是模糊文本
与对象边界一起收敛，避免"枚举规整了、边界还乱着"的半成品状态
发布口径：文档与代码同源（注解驱动），枚举契约影响对接方取值方式——升级说明见 release notes
同期工程化：前端迁移 pnpm + Pinia 组合式 store，utils.ts 拆分聚焦模块；Netty UDP/TCP 服务升级 MultiThreadIoEventLoopGroup——底座小步现代化
文档重构：仓库文档大重组与工程笔记归档（提交 69e5fbe0a），为后续在线书与 docs 站五支柱重构铺路
