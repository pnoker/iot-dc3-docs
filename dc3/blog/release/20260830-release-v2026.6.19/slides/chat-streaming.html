IoT DC3 · Release R2 v2026.6.19 · 特性详解 1/3

AI Chat 流式体验：推理可见、偏好跟随、回答即答即流

2026 上半年 800+ 提交的 AI 主线，落在用户体验上的三个点
做了什么
流式输出：回答按 token 流式呈现，配 streaming 性能优化——首字时间与长回答的体感大幅改善
推理过程展示：reasoning 内容独立渲染、可展开收起——模型"怎么想的"不再黑箱
i18n 全覆盖：AI 界面文案多语言化
怎么做的 · 两个关键决策
偏好持久化到会话：模型选择 / temperature / 推理开关 / requireConfirmation 等用户设置从 localStorage 迁到会话持久化——换设备登录偏好还在（提交 42ee486f9 与其前置修复）
里程碑全程跟进：Spring AI 从 2.0.0-M5 升到 M6（提交 67f1f7c2c），流式 API 的行为变化在平台侧吸收，前端只感知最终形态
numValue 数值投影下推驱动侧（提交 712506b32）：数值过滤在数据源头完成——AI 查数更快，数据中心更省
为什么这样做
流式是 AI 产品的呼吸感。工业问答往往要聚合大量点位数据，等待整段返回的体感是"卡死"；流式 + 推理可见，让用户知道系统在思考什么。
偏好属于会话不属于浏览器。localStorage 换台机器就丢——运维人员在值班室和大屏上会切换使用，偏好跟随账号才是正解。
计算下推是数据库常识。能在驱动侧过滤就不在数据中心过滤，这条从数据库界抄来的纪律同样适用于采集链路。
里程碑口径说明：M5 / M6 为 Spring AI 2.0 的开发里程碑，2.0.0 正式版迁移在下一个版本（v2026.6.26）完成
