发布工程：docker-ci 自动发布波次与运行时资源画像

2025 年 8 月上线的工作流，让"打 tag 即出双语文档的 GitHub Release"成为常态
docker-ci 工作流 · 怎么做的
1
tag 触发
dc3.release.* / dc3.develop.* 双模式：release 出正式镜像，develop 出日常构建——发布与日常验证同一条流水线
2
双语 Release Notes 自动生成
CHANGE / TITLE / USAGE 模板 + envsubst 变量展开，GitHub Release 带可折叠双语段落与架构图——发版文档不再手写
3
产物归档
使用文档（USAGE.md）与变更记录（CHANGE.md）随 release 归档到 dc3/doc，每个版本自带说明书
运行时资源画像
APM agent 接入：所有 Dockerfile 与 compose 增加统一的 APM agent 环境变量与 dc3-apm 服务位——生产可观测从容器层开始
JVM 堆 1024m → 512m：逐服务实测后统一收紧，容器密度翻倍，资源画像更贴近真实负载
JAVA_OPS 顺序规范与 GC 日志配置补齐——同类参数写法一致，排障不再猜
center-single 测试档：单体形态补齐 RabbitMQ / Mongo / gRPC / MQTT 测试配置
为什么单独讲：这一套发布工程沿用至今——本系列 6 篇文章对应的每一个 tag，都是这条流水线产出的
