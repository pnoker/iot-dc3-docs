IoT DC3 · Release R1 · 2025 年度版 · 特性详解 1/3

架构瘦身：减掉的每一项都有明确的理由

2025 年的演进主线不是加功能，是把历史包袱一次清干净——瘦身之后，数据底座只剩一条主线
移除什么
REMOVEMongo 模块整体退场：点位存储改由 PostgreSQL 承接，少维护一套存储依赖
REMOVELimitedIp 限流特性：连同 gRPC / DAL / proto 定义一并移除，认证链路回归单一职责
REMOVE冗余 Redis 依赖：网关响应式 Redis 限流配置与未用依赖清理
REMOVE旧事件链路：EventService 移除，事件能力由 DeviceEvent / DriverEvent 专用 DAL 重建
收敛为什么
CONVERGE点位存储统一 PostgreSQL：传感器数据本就是关系+时序形态，一套存储一套备份
CONVERGE事件底座重建：DeviceEvent / DriverEvent 独立 DAL、DO、Mapper，为事件溯源铺路
CONVERGE时间字段全线 LocalDateTime：DO 模型与 gRPC builder 类型一次对齐
CONVERGE可观测与资源：APM agent 接入、JVM 堆 1024m → 512m，容器资源画像更精准
为什么做减法
每多一种存储，就多一份运维、备份与故障面。8 年项目最贵的是历史包袱——2025 年把"可能用得上"的模块清掉，只留"确实在用"的。
为什么选 PostgreSQL
点位是高频写入的结构化数据，PG 的批量写入与生态（后续 TimescaleDB 扩展）长期收益远高于双存储并存。
为什么顺便修发布
瘦身的同时 docker-ci 重构为自动发布波次——底座收敛与发布工程同步，避免"瘦了身发不出版"。
瘦身不是删代码，是把架构决策重新做一遍——每一条移除都对应一条更明确的收敛路径
