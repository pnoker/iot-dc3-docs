贡献代码 · 四步标准流
1
Fork 仓库，拉 feature 分支 从 main 拉出
分支命名：feature/你的名字/功能描述，例如 feature/pnoker/mqtt_driver
2
开发并提交 Conventional Commits
feat: / fix: / docs: 前缀 · 仓库装有提交信息校验钩子（make install-hooks）
3
PR 提交到 develop 分支
维护者 review 后合并 · 提交前按改动跑对应验证（编译 / 测试 / compose 校验）
4
非代码贡献同样欢迎
文档纠错、双语书英文校对、Issue 复现信息，都是高价值贡献
热门方向 新协议驱动（SDK 路径） 文档与翻译 前端体验（Vue 3 + TS） CLI 工具面扩展
AGPL 3.0 · 三条大白话
✓
个人学习、研究、公司内部使用：免费
不需要开源你的内部业务代码，放心用
✓
修改了代码：按 AGPL 3.0 开源你的修改
改好了回馈社区，正是项目十年来的演进方式
!
闭源商用：需要商业授权
对第三方提供商业服务而不开源修改 → 联系仓库 LICENSE.txt 渠道洽谈
开源不是"随便拿"，也不是"不能用"——规则清楚，合作才长久；许可原文以仓库 LICENSE 文件为准
