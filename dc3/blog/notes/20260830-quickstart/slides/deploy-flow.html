IoT DC3 · 开源工业物联网手记 · EP.08

四步部署流程：从 clone 到看到数据流动

评估开源平台，"从 clone 到看到数据"的耗时是最诚实的指标 · 本文口径以当前主干为准
前置条件 JDK 21 Maven 3.9+ Podman 或 Docker clone：github.com/pnoker/iot-dc3 国内网络用 -cn 后缀目标走阿里云源
STEP 1 起基础设施Infra Up make up-db compose 启动 PostgreSQL（TimescaleDB + pgvector + AGE 定制镜像）与 RabbitMQ
产出：数据库 + 消息总线就绪
STEP 2 编译打包Package source dc3/env/dev.env.sh mvn -s .mvn/settings.xml clean package 首次编译拉依赖，耗时视网络；只验编译可用 -DskipTests compile
产出：各服务可运行 jar
STEP 3 起全栈服务Stack Up make up-dev 网关、四大中心服务、驱动逐一启动；可观测栈按需 make up-optional
产出：平台全栈在线
STEP 4 浏览器验证Verify http://localhost:8080 登录后启用 Virtual 虚拟驱动——模拟设备持续上报，整条链路立刻可验证
验收：不接真设备，数据流动可见
常见坑位（我们自己跌过）
8080 被其他服务占用
症状是前端"起来了"但页面空白 → 换个端口最省事
首次起库失败后反复重启
seed 初始化只在空数据卷执行 → make down 后确认卷已清理再试
国内拉镜像慢 / 超时
一律用 -cn 后缀的 make 目标（阿里云镜像源）
细粒度报错没头绪
docs.dc3.site 的 Troubleshooting 按报错关键字查，比搜索引擎快
跑通之后 · 可选下一步
导入演示数据集：demo/iot-dc3-demo.sql 手动执行，获得预置设备与点位（不自动运行）
体验 AI Chat：配置模型后用自然语言查设备与点位（EP.06）
接真实设备：时间花在协议与点位建模上——那是 EP.02 的内容，与部署无关
生产部署：K8s / Helm / Swarm 配置与 TLS 见 dc3/doc/DEPLOYMENT.md
耗时口径：链路跑通约一杯咖啡（视网络）· compose 流程适合开发与体验，生产另有部署指南
