IoT DC3 · 开源工业物联网手记 · EP.05

换型三步走，以及"诚实降级"的完整链路

同一时刻只激活一个时序库 · 数据库不支持的能力由门面接住，语义不变形
换型操作 · 三步
1起目标存储容器
make up STACK=optional SERVICES="tdengine"
influxdb / iotdb 同款写法 · IoTDB 首启自动挂载微秒精度配置（必需）
2改激活类型与连接变量
DC3_TSDB_TYPE=tdengine # 默认 timescale
URL / Token / Host 按需覆盖 · 同时只激活一个适配器
3数据中心换依赖打包
<artifactId>dc3-tsdb-tdengine</artifactId>
默认只打包 timescale · 其余按部署显式引入，不付无用 jar 开销
与 MQ 家族同款约定 · 时区口径全家族锁定 DEFAULT_ZONEID，不是 UTC
数据库不支持时，会发生什么
1
某能力该库没有
例：InfluxDB / IoTDB 无 PERCENTILE 函数
2
适配器如实声明 false
能力矩阵显式登记，不猜、不模拟、不报错糊弄
3
TCK 按能力门控跳过
跳过数公开（2 / 2 / 3 例）· 跳过不是测试失败
4
数据中心门面降级接住
延迟直方图返回零桶 · 分位数 / 相关系数由门面从有界拉取数据中自算 · 面板空桶自行补零
选型与使用边界
空桶补零四库均不做：分桶读省略空桶（gapFill=false），由消费端补零——刻意的语义统一
rollup 仅 Timescale 原生：共享 real-time 连续聚合；纯 PG 部署启动时协商降级为 NONE，读走原始扫描
信创场景：TDengine / IoTDB 已过契约验证；生产容量规划仍需按自身数据量实测
时区口径：全家族锁定 DEFAULT_ZONEID（随部署时区），不是 UTC——隐性差异最容易被忽略
价值取向：宁可少给能力，绝不给错数据——抽象层不悄悄改变语义
换型成本排序：改配置 < 换依赖，永远不用改业务代码 · 时序家族与 MQ 家族同一套 core + TCK 范式
