# 控制台 · 位号与模板

位号与模板是数据的"定义侧"：模板描述一类设备有哪些能力（位号/指令/事件），位号挂在模板下承载实际数据。这页讲在控制台上怎么管理这两层——新增模板、给模板配位号、把设备绑到模板上，以及每个界面动作背后的 API。

> 你在这里：已在[设备管理](./console-devices)里建过设备，现在要定义"这台设备有哪些数据"。字段与对象模型见[模板](../introduction/concepts/profile)与[位号](../introduction/concepts/point)；属性怎么填见[属性与配置](../introduction/concepts/attribute-config)。

## 模板管理

打开**模板管理**。页面结构与设备管理一致：工具栏（检索/筛选/**新增**）+ 模板卡片列表 + 分页；卡片上直接提供 启用/停用（物模型开关）、删除。

**新增模板**：填名称、编码（`profileCode`，租户内唯一）后保存——模板本身只是"壳"，能力靠下面的位号/指令/事件定义。

**模板详情**四个页签：

| 页签 | 内容 |
|------|------|
| 模板信息 | 名称、编码、启用状态等基本字段 |
| 关联位号 | 该模板定义的全部位号（配置读写属性、单位、类型） |
| 关联指令 | 设备级自定义指令定义 |
| 关联事件 | 事件定义（驱动上报的外部事件） |

停用模板（物模型开关关闭）后，其下设备的能力定义不再参与采集与命令校验——批量暂停一类设备时比逐台停用设备更省事。

## 位号管理

打开**位号**（从模板详情的"关联位号"页签进入，或导航直达）。工具栏支持按设备/模板/名称检索与启用状态筛选；卡片动作：**编辑**、启用/停用、删除、详情。

**新增/编辑位号**的关键字段：

| 字段 | 说明 |
|------|------|
| 名称 / 编码 | 展示名 + `pointCode`（同一模板下唯一） |
| 读写类型 | `rwFlag`：只读 / 只写 / 读写——决定能否下写命令 |
| 单位与精度 | 展示与换算用 |
| 驱动属性配置 | 该位号在本驱动协议下的取值参数（如 Modbus 的 slaveId/functionCode/offset）——**位号级读写命令的取值来源就是这里**，不是指令属性 |

位号值的读写语义（latest/list 接口、命令轮询）见[数据与命令](./data-commands)。

## 界面动作与 API 的对应

| 界面动作 | API（经网关，manager 中心） | 语义 |
|---------|---------------------------|------|
| 模板检索 | `POST …/profile/list` | 分页查询，租户隔离 |
| 新增模板 | `POST …/profile/add` | 建模板（不回传 ID） |
| 模板启停 | `POST …/profile/update`（enableFlag） | 物模型开关 |
| 位号检索 | `POST …/point/list` | 支持按设备/模板过滤 |
| 新增/编辑位号 | `POST …/point/add` / `…/point/update` | 含属性配置一起提交 |
| 位号启停/删除 | `…/point/update` / `…/point/delete` | |
