# 控制台 · 设备管理

设备管理是 Web 控制台里使用频率最高的页面：接入、检索、启停、删除设备都在这里完成。这页按"打开页面 → 找到设备 → 做出变更"的顺序讲清每个操作，并说明界面动作对应到哪条 API——方便你在页面上点不动时，知道日志和接口层面到底发生了什么。

> 你在这里：栈已起、[驱动已就绪](../drivers/)，想在界面上管理设备而不是调 API。接入流程的完整语境（含属性含义）见[设备接入流程](./device-onboarding)；设备的字段与 API 语义见[设备概念](../introduction/concepts/device)。

## 打开页面

登录后进入 **设备管理**（导航：设备管理）。页面由三部分组成：

- **工具栏**：检索与筛选（见下）、**新增**、**导入**；
- **设备卡片列表**：每台设备一张卡，卡上直接提供 启用/停用、删除；
- **分页与排序**：底部分页器可切换每页条数与页码，工具栏可刷新、按列排序。

## 找到设备：筛选与检索

工具栏提供三类过滤条件，组合生效：

| 条件 | 说明 |
|------|------|
| 设备名称 | 按名称模糊检索 |
| 驱动 | 下拉选择驱动（选项来自驱动字典，可刷新重载） |
| 启用状态 | 分段选择：全部 / 启用 / 停用 |

检索走的是管理中心的设备分页接口（`POST /device/list` 语义），结果按当前租户隔离——你永远看不到其他租户的设备。

## 新增一台设备

1. 工具栏点 **新增**，弹出表单；
2. 填写设备名称、选择**驱动**与**模板（Profile）**——这两项决定设备能承载哪些位号与指令（见[模板](../introduction/concepts/profile)）；
3. 按驱动的属性定义补全连接配置（如 Modbus 的 host/port）：属性从哪来看[属性与配置](../introduction/concepts/attribute-config)；
4. 保存。新设备默认进入启用/停用状态取决于表单选择，未接入真实设备前可先停用。

创建动作对应 `POST /device/add`（不回传 ID，按名称回查——见[设备概念](../introduction/concepts/device)的 API 表）。

## 批量导入

工具栏点 **导入**：先**下载模板**，按模板填写后上传。导入逐行校验，失败行会给出原因。适合一次性录入成批同类设备（如同一网关下的多块仪表）。

## 启用 / 停用 / 删除

设备卡片上直接操作：

- **停用**：设备退出采集（位号不再更新），配置保留，随时可重新启用；
- **启用**：恢复采集，驱动重新建立连接；
- **删除**：移除设备及其关联配置，**不可撤销**——删除前确认位号数据是否已导出（历史位号值按保留策略独立留存，不随设备删除立即消失，但查询入口会失去设备维度）。

## 设备详情

点击卡片进入**设备详情**，三个页签：

| 页签 | 内容 |
|------|------|
| 设备信息 | 名称、所属驱动、模板（名称与编码）、启用状态等基本字段 |
| 关联位号 | 该设备下全部位号的清单与状态，可由此跳到位号配置 |
| 关联指令 | 该设备绑定的指令（自定义指令）清单 |

详情页是排查"这台设备为什么不采数"的起点：驱动名加载失败会在页内提示（通常是驱动已离线或被删除）。

## 界面动作与 API 的对应

| 界面动作 | API（经网关） | 语义 |
|---------|--------------|------|
| 检索/筛选 | `POST …/device/list` | 分页查询，租户隔离 |
| 新增 | `POST …/device/add` | 建设备，不回传 ID |
| 编辑 | `POST …/device/update` | 改名称/模板/配置 |
| 启用/停用 | `POST …/device/update`（enableFlag） | 切换启用状态 |
| 删除 | `POST …/device/delete` | 删除设备 |

界面上每一步都能用 curl 复刻——鉴权与请求形态见 [API 文档](../development/api-documentation)。
